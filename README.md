# Farmstead

A top-down farming RPG for the browser. Plain ES modules and an HTML canvas, with no build step and no runtime dependencies.

Design source of truth: [`docs/GAME_DESIGN.md`](docs/GAME_DESIGN.md) · Art benchmark: [`docs/reference/approved_starting_area_reference.jpg`](docs/reference/approved_starting_area_reference.jpg) · Asset log: [`docs/ASSETS.md`](docs/ASSETS.md) · Status: [`docs/STATUS.md`](docs/STATUS.md)

## Play

```bash
npm start            # http://localhost:8080
```

| Action | Keyboard | Touch |
|---|---|---|
| Move | WASD / arrows | on-screen stick |
| Interact (contextual: till, plant, water, harvest, use buildings) | E / Space | **A** button |
| Choose seeds / tool | 1–9 | tap hotbar slot |
| Bag / Journal / Menu | B / J / Esc | top-right buttons |
| Claim a completed quest | Enter | **Claim** button in the tracker |

## Test

```bash
npm test             # unit tests (node:test) for all gameplay systems
npm run test:e2e     # Playwright playthrough of the full loop; screenshots in test-results/
```

## Architecture

```
index.html, styles.css      DOM shell: canvas + HUD + modal panels
src/config.js               engine/world constants
src/data/                   data-driven definitions: crops, items, quests, shop/upgrades, world layout
src/core/                   event bus, seeded RNG
src/systems/                pure gameplay logic (no DOM): inventory, farming, economy, quests,
                            time, simulation (shared clock), state, save (versioned + validated)
src/world/                  layout -> drawables/colliders, collision, camera
src/render/                 painted ground builder, y-sorted renderer, sprite mapping, effects
src/ui/                     HUD and panels (shop, upgrades, bag, journal, menu, dialogs)
src/input/, src/audio/      keyboard/touch input, sound effects
src/game.js, src/main.js    orchestration and bootstrap
assets/                     runtime art + manifest.json (generated by tools/import_assets.py)
tools/import_assets.py      phase-pack import pipeline
tests/                      unit + e2e
```

Gameplay systems change `state` and emit events on the `EventBus`. Quests, audio and HUD toasts subscribe to those events, so quest progress always comes from real actions. Every sprite is looked up by manifest key, so a placeholder can be swapped by regenerating the manifest without touching code.
